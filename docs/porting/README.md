# HBM Forge 1.20.1 port

The parity baseline is commit `9d7b7ca3bc999b7909fdb349738d305dff58bd7d` on the 1.7.10 `master` branch. This branch builds only `src/forge120`; the original `src/main` implementation remains as a reference. The old Gradle properties are preserved in `gradle-1.7.10.properties`.

`legacy-inventory.csv` is a source-linked audit index. Generate it with `python tools/porting/build_inventory.py` and verify it with `--check`. Put implementation status and evidence in `status.csv`; do not edit the generated inventory directly. `partial` means the content exists but its original behavior or acceptance checks are incomplete. `verified` requires a runtime or asset comparison check, not merely a compiled class. The scanner covers every legacy Java file and asset and identifies direct and helper-registered blocks, config-option and recipe-definition call sites, including the central `CraftingManager.addRecipeAuto` calls. It remains a static candidate list, not an exhaustive inventory of conditional, loop-generated, or JSON-loaded runtime recipes. Screen and worldgen source files likewise need individual behavior checks before their categories can be declared complete. See [the parity and acceptance matrix](parity-matrix.md).

## Client smoke

Run `./gradlew runClientSmoke --no-daemon`. The isolated `run-client-smoke` directory permits a first-run accessibility menu; the task stops after a menu appears, all thirteen socket OBJ layers pass the bake audit, and the Insulator inventory model resolves. CI runs it under Xvfb. This does not check in-world rendering or gameplay.

## Dedicated restart smoke

Run these in order in the same checkout and `run` directory. The first process writes radiation SavedData, a battery fixture with HE, controls, and an item, a cross-chunk cable fixture, a battery socket whose 2x2 footprint crosses a chunk border, and a second socket holding a charged quantum pack. The second starts a new dedicated GameTest server, checks all fixtures and transfer, then clears them. CI runs the same pair.

```sh
./gradlew build runGameTestServer -PhbmPersistencePhase=seed --no-daemon
./gradlew runGameTestServer -PhbmPersistencePhase=verify --no-daemon
```

## Ore config smoke

These runs use a separate `run-ore-config` world. Install each checked-in config fixture before starting its server; the test never edits Forge config values while chunks are generating.

```sh
mkdir -p run-ore-config/world/serverconfig
cp tools/porting/fixtures/hbm-server-master-off.toml run-ore-config/world/serverconfig/hbm-server.toml
./gradlew runOreConfigGameTestServer -PhbmOreConfigPhase=master-off --no-daemon
cp tools/porting/fixtures/hbm-server-copper-off.toml run-ore-config/world/serverconfig/hbm-server.toml
./gradlew runOreConfigGameTestServer -PhbmOreConfigPhase=copper-off --no-daemon
cp tools/porting/fixtures/hbm-server-copper-high.toml run-ore-config/world/serverconfig/hbm-server.toml
./gradlew runOreConfigGameTestServer -PhbmOreConfigPhase=copper-high --no-daemon
```
